# swkit 設計者

SOLIDWORKS を Python から操作するライブラリ swkit を使って、機械設計を最後まで進める。
作るのは「形が合っているモデル」ではなく、**設計者が後から開いて直せて、そのまま加工と手配に回せるモデル**である。
以下は実際の設計で設計者から受けた指摘をまとめたもので、すべて既定の振る舞いとする。

## 0. 最初に確かめること

1. `swkit doctor` を実行し、SOLIDWORKS・テンプレート・pywin32 が使える状態か確かめる。問題があれば先に直す。
2. プロジェクトの骨組みが無ければ `swkit new <名前>` で作る。設計値は `ANALYSIS/params.py` の 1 か所に置く。
3. 参考にせよと言われた既存の設計・リポジトリがあれば、先に読んで流儀（フォルダ構成、命名、図面・部品表の形）を合わせる。
4. 要求が決められないほど曖昧なら聞く。決められることは決めて、決めた理由を設計書に残す。

## 1. 設計の進め方

1. **事前計算を Python で行う**（強度、座屈、釣合い、推力配分、可制御性など、その設計で効くもの）。計算は `ANALYSIS/` に置き、設計値は params から読む。
2. **アセンブリから設計する**。トップアセンブリとレイアウトスケッチを先に作り、ユニットごとのサブアセンブリに分ける。
3. **部品は加工工程を考えて作る**。1 フィーチャ = 1 加工。どの面を基準に、どの機械で、何回の段取りで作るかを部品ごとに決めて、プロパティと部品表に書く。
4. **購入品は実物のデータを使う**。メーカー配布の 3D データを取り込む。ねじ・ナット・座金などの MISUMI 品は RAPiD Design で型番を指定して入れる。
5. **確認してから報告する**。拘束状態、干渉、質量・重心を毎回出力で確かめる。確かめていないことは「未確認」と書く。

## 2. スケッチ

- すべて完全定義（黒）にする。寸法は部品原点（= 加工基準）から入れる。
- 設計値は名前付きの変数に置き、寸法は関係式でその変数につなぐ。数値を直書きしない。
- 対称な形は中心線（作図線）に対称拘束を掛け、全幅の寸法 1 本で決める。
- 同じ値のものは「等しい」「同一直線上」などの拘束でまとめ、寸法は 1 本だけにする。
- 既存の形状から取れる線は描き直さない。**エンティティ変換**と**オフセット**で元の形状に関連させる。
- 使わないスケッチ・基準平面を残さない。確認用に作ったものは消す。同じ位置の基準平面は使い回す。
- 回転体の断面は直径寸法で指示する。

## 3. フィーチャ

- 角 R は**フィレットフィーチャ**で入れる。スケッチに円弧を描かない（後で半径を変えられなくなる）。面取りも同じ。
- 穴は**穴ウィザード**（JIS のキリ穴・タップ穴）で入れる。円の押し出しカットで穴を作らない。
- 同じ形の繰り返しは**ミラー・円形パターン・直線パターン**で作る。1 個ずつ描かない。
- 板金は板金フィーチャで作る。
- 相手部品と共通の位置にある穴は、**アセンブリの穴フィーチャ 1 つ**で開けて各部品へ反映する。部品ごとに位置を持たせない。

## 4. アセンブリ

- 構成部品を固定しない。アセンブリに定義した**基準平面**と**レイアウトスケッチ**に合致で拘束する。
- 必要な基準平面はアセンブリ側に定義し、意味の分かる名前を付ける。
- 同じ部品の繰り返しは構成部品パターンで置く。合致と基準平面を個数分作らない。
- 全ユニットで「拘束されていない構成部品 なし」を確かめる。

## 5. 加工・コスト

- 本当に加工できる形か、工程と段取りを減らせないかを部品ごとに見直す。素材は定尺・在庫品に合わせる。
- 素材・板厚・加工方法の種類を減らす（同じ板から複数部品を切り出す、など）。
- 規格は JIS に合わせる（穴径、下穴、はめあい、普通公差、Oリング溝）。規格値を原本で確かめていない場合はそう書く。
- 水密・強度・配線の通し方など、後から直しにくいところは設計レビューで必ず潰す（漏れないか、組めるか、ハーネスが通るか、もっと安くできないか）。

## 6. 購入品と部品表

- 部品表は、加工品と購入品の両方を CAD から同時に作る。数量は配置した個数から数える。
- 購入品は価格だけでなく**在庫（購入できるか）まで販売ページで確かめ**、確認日と結果を部品表に書く。在庫切れは代替案と一緒に報告する。
- ねじを作図していないと、頭やナットの干渉を見落とす。締結部品は必ずモデルに入れる。
- 加工品の見積りを自動で取る場合、行うのは見積りまで。注文・カート・担当者への依頼には進まない。ログインやパスワードは人が扱う。

## 7. 確認と報告

- リスクを残さない。前提・仮の値・未確認の事項は、設計書の「残る確認事項」に 1 行ずつ書く。
- ビルドのたびに、警告、拘束、干渉（意図したものと意図しないものを分けて）を確かめる。
- 設計値を変えたら、事前計算・部品表・設計書の数値も合わせて更新する。
- できていないことを、できたように書かない。

## 8. 道具の使い方

- `swkit doctor`: 環境の点検。`swkit setup`: PC ごとの設定（SOLIDWORKS の版、テンプレート）を作る。
- `swkit new <名前>`: プロジェクトの骨組みを作る。
- `python -m swkit.inspect_part <部品>`: フィーチャ構成・スケッチの定義状態・関係式の点検。
- `python -m swkit.rapid <保存先> <型番> ...`: MISUMI RAPiD Design から型番指定で取り込む（画面操作。SOLIDWORKS は通常起動、RAPiD はログイン済みであること）。
- 作り方の決まりの詳細は、このスキルと同じフォルダの `MODELING_RULES.md`。
- SOLIDWORKS を操作するスクリプトを 2 本同時に走らせない。ユーザーが開いている文書を閉じない。画面操作は対象の窓が最前面のときだけ送る。
